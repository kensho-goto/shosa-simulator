# 所作の台帳（items / scenarios）の読み方

収録する200項目（S001〜S200）と、場面（シナリオ）との対応をまとめた台帳です。

| ファイル | 中身 |
|---|---|
| `data/items.json` | 200項目。`{ version, generatedBy, items: [...] }` |
| `data/scenarios.json` | 場面の一覧と、場面に入る項目。`{ version, generatedBy, scenarios: [...] }` |
| `tools/canonical-items.mjs` | 200項目の名前と分類の正本（依頼文の一覧そのまま） |
| `tools/item-data/*.mjs` | 項目ごとの中身（目的・失敗例など） |
| `tools/build-items.mjs` | 上の2つと出典・場面の定義から JSON を作る |
| `tools/validate-items.mjs` | 検査。問題があれば終了コード1 |

直すときは `tools/` 側を直して、次の2つを順に打つ。JSON を手で直した場合も検査は必ず通す。

```sh
node tools/build-items.mjs
node tools/validate-items.mjs
```

## 項目のフィールド

| キー | 意味 |
|---|---|
| `id` / `name` / `category` | 正本どおりのID・名前・13分類。名前は一字一句変えない |
| `kind` | `儀式全体`（行事のまとまり）／`個別動作`（ひとつの所作）／`慣習`（季節や暮らしの習わし） |
| `parents` | その所作を含む儀式・行事の項目ID。200項目の中に妥当な親があるときだけ入れる（例：S172 刈初の儀 → S171 地鎮祭） |
| `scenarios` | 入っている場面のID。`scenarios.json` の `items` と必ず一致させる |
| `playerRole` | プレイヤーの立場（招かれた人・参加者・手伝い役・進行役・見学者など） |
| `controls` | 共通操作の系統。`姿勢`・`物の扱い`・`傾きと量`・`タイミング`・`発言と視線`・`順序と配置` だけを使う |
| `goal` / `prerequisites` / `successCriteria` | 目的・始まる前の状態・成功とみなす条件 |
| `failures` | 失敗例。`example`（やってしまうこと）・`reaction`（場の反応）・`recovery`（立て直す手段） |
| `needs` | 作るのに要るもの。`people`（人）・`props`（道具）・`motions`（動作）・`sounds`（音） |
| `sources` | 出典。`status` は `確認済み`（2026-11-23 に実際に読んで記述を確かめた）か `未確認`。未確認の `checkedOn` は `null` |
| `variations` | 地域・宗派・流派・家庭による違い。断定しない。わからないものは「未確認」と書く |
| `gameExaggeration` | ゲームで加える架空の演出。実在の作法と混ざらないよう「架空の演出として」と書く |
| `status` | 実装状態（下の決まり） |
| `notes` | 補足。出典で何を確かめたか、扱いに配慮が要ることなど |

### 書き方の決まり

- 「昔からある」「日本にしかない」「全国で同じ正解」とは書かない。実在の作法（`goal`・`successCriteria`）、違い（`variations`）、ゲームの誇張（`gameExaggeration`）を分けて書く。
- 葬送の項目（S081〜S095 など）は笑いをとる誇張をしない。来訪神（S181〜S184）は実在の地域の行事と明示し、面や衣装は実物を複製しない架空のデザインにする。
- 項目名が「出す側・案内する側」の動作で、場面では受ける側になるもの（S029 お茶出し、S030 玄関でのお見送り、S162 エレベーターの乗降・案内、S166 来客を案内する）は、場面では受ける側として判定し、`notes` にその旨を書く。出す側の操作は将来の役替えで使う。

## 実装状態（status）の決まり

| 値 | 付けてよい条件 | 誰が上げるか |
|---|---|---|
| `未着手` | 既定 | — |
| `仕様済み` | 場面A/B/C（SC-A・SC-B・SC-C）に入り、`goal`・`successCriteria`・`failures` が書けている | 台帳の生成スクリプト |
| `操作可能` | ゲームの中で、その所作をプレイヤーが実際に操作でき、成功・失敗の判定が動く | ゲームの担当者（動作を確かめてから） |
| `演出済み` | 操作に加えて、反応・音・誇張の演出が入っている | ゲームの担当者 |
| `検証済み` | 人が通しで遊んで、成功・失敗・立て直しを確かめた | ゲームの担当者 |

- 図鑑やメニューに名前を載せただけ、説明文を出しただけでは `操作可能` にしない。
- 他の項目の操作を流用して同じ判定が動く場合も、その項目の場面で確かめてから上げる。
- 検査は `操作可能` 以上があると注意を出す（エラーにはしない）。

## 場面A/B/Cの次に作る順番（案）

共通操作と、部屋・道具・人物の資産を使い回しやすい順。

1. **SC-H 和食の会席** — SC-A の和室・正座・座礼をそのまま使い、新しく作るのは箸と椀の「物の扱い」だけ。
2. **SC-D 両家顔合わせ** — SC-A の人物と SC-H の膳を使い、お酌・盃の「傾きと量」を足す。
3. **SC-I 宴会・酒席** — SC-D の酒器と乾杯をそのまま使い、手締めの「タイミング」を足す。
4. **SC-G 神前結婚式** — SC-C の神社と拝礼、SC-D の盃を使う。玉串（S014）は SC-N・SC-Y でも使い回せる。
5. **SC-V 贈り物の準備 → SC-E 結納** — 袱紗・水引・熨斗を先に作ると、結納・葬儀・七五三・地鎮祭で使い回せる。結納の部屋は SC-D を流用。
6. **SC-J 茶会** — 正座・座礼・膝進（S025）と、茶碗を回す「傾きと量」。初釜（S125）もここで扱える。
7. **SC-S 正月・SC-L・SC-M・SC-N** — SC-C の神社と初穂料（S106）を使い回す行事の章。
8. **SC-P 法事と墓参り → SC-O 通夜・葬儀** — 数珠・焼香の操作は共通。演出の配慮が要るので、判定の厳しさと表現を先に決めてから作る。
9. そのほか（季節の行事、仕事、住まい、祭り、来訪神、和装、武道、入浴）は、使う資産がほかと重なりにくいので後に回す。

## 出典

確認済みの出典は10件（2026-11-23 に読んで確かめたもの）。神社本庁の「神前結婚式」「参拝方法」のページは、この日はメンテナンス中（HTTP 503）で読めなかったため、URL は入れて `未確認` にしている。読めるようになったら確かめて、`tools/build-items.mjs` の `SOURCES` の `ok` を `true` にして作り直す。
